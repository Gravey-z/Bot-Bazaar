# Local development with one command

From the repository root:

```powershell
corepack pnpm dev:web
```

Open http://127.0.0.1:4200/?town=phaser. The launcher builds the shared packages and worker, then starts the read-only town reader, the configured guest backend, the matching AI merchant runtime and the Angular watch/preview process. It sets the reader URL and guest proxy URL automatically. Ctrl+C requests shutdown of its own processes, including through IPC on Windows; it does not kill independently started services. Stop old manually started readers, web servers or merchant runtimes first to release their ports and journals.

Source changes to the worker require restarting this command. Angular changes rebuild in watch mode. No tests run as part of the launcher. The launcher itself has not been executed or validated during implementation.

If the public RPC returns HTTP 429, browsers may also report a CORS error because the provider's throttling response lacks an allowed-origin header. Town clients now pace and deduplicate requests, cache immutable block reads, and use a 15–60 second cooldown for transport failures/throttling. Backend bounded RPC clients also pause after an explicit 429. The clients continue to require verified chain evidence and do not assume success while unavailable. After restarting for these changes, allow a minute for a provider limit to clear; repeatedly refreshing can prolong throttling. The `Near Connect Version` console message is informational. These source changes have not been tested.

Follow-on fix: the local town frontend now sends these SDK reads to `/api/town-rpc` on its own origin. The preview server forwards only public read/receipt methods to fixed approved Testnet providers, with a bounded queue, immutable-read cache and per-provider cooldown/fallback. It forwards no cookies, authorization headers, signing keys or transaction broadcasts. Existing SDK deployment/code/receipt verification still applies to responses. Nonlocal deployments continue to use their configured RPC directly. A provider outage can still make reads unavailable; it is no longer surfaced as a browser CORS failure for the local town read path. Restart dev:web to load this server route, then hard-refresh the browser. The SVG favicon is now explicitly included in Angular's asset list too. These fixes remain unverified; no builds or services were run while editing them.

Guest gas correction: NEP-642 requires purchasing receipt gas at a minimum of 10^9 yoctoNEAR per gas, so attaching 100 Tgas requires over 0.1 NEAR upfront despite a lower burn price. 1. Copy `config/living-town-guest.example.json` to `data/living-town-guest.local.json`.
2. Set `profile_file` to the absolute path of `config/living-town-testnet.json`, and `parent_account_id` to your dedicated funded guest parent.
3. Set `frontend_origin` to `http://127.0.0.1:4200`, `port` to `3013`, and `trusted_proxy_ips` to `["127.0.0.1"]` for the local web proxy. Preserve the example funding/action limits unless you intend to change them.
4. Set all filesystem fields to absolute paths. Choose a private `data_dir` for guest custody, a separate `funding_witness_file`, and a public `receipt_outbox` matching the reader's `receipt_inbox`. Keep custody files and secrets outside web public assets and the public receipt directory.
5. Provide the private `encryption_key_file` and `funder_key_file`. The encryption file must contain a stable random 32-byte key as `{ "key_base64": "<base64>" }`. The parent signer file must contain exactly `account_id`, `public_key` and `private_key`, with the matching `ed25519:` public/private key pair for that dedicated parent. These are files you provide locally; no values need to be pasted into chat. Never put either file into frontend assets or source control. Keep the encryption key and funding witness across restarts. On Linux, secret file permissions must be owner-only.

See [guest implementation notes](../../Bot%20Bazaar%20docks/No%20wallet/PHASE-1-2-GUEST-SESSIONS-AND-PROVISIONING.md) for custody, funding and file requirements. Once this configuration is present, `dev:web` starts the guest backend and connects the same-origin proxy automatically. Without it, the launcher prints a setup message and supports wallet play and public browsing.

Starting a configured guest backend resumes its existing provisioner/action journal. Clicking Play as Guest can reserve and spend Testnet funding within its persistent limits. An existing account/journal is never reset by this launcher.

## Reader and persistent state

The launcher uses `data/living-town-reader.local.json`. If absent, it creates a local reader configuration from the reviewed deployment profile with a new `data/dev/projection` folder. Existing reader configuration is retained; its origin must allow the frontend and its receipt inbox must match the configured guest outbox.

Only an empty database directory receives `--initialize` automatically. A missing database in a nonempty directory stops startup so established state is preserved. Existing guest databases still require their original encryption key, funding witness and compatible configuration. This launcher does not perform migrations or reset funding history.

Optional overrides can be saved once in ignored `.env.dev.local` at the repository root:
